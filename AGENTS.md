# EasyPost USPS Label - Project Rules

Take-home prototype with a 4-hour time box. Stack fixed by the assignment: Laravel 13 (PHP 8.3),
React, MySQL. Users authenticate, generate USPS shipping labels through EasyPost, print them, and
browse their own label history. The rules in this section take precedence over the generated
Laravel Boost guidelines below whenever they conflict.

## Scope: 4-hour prototype

- Every feature must map to a requirement in the assignment: user credentials, US-only from/to
  addresses, package weight and dimensions, label generation via EasyPost, a printable label,
  persistent storage of labels, per-user label history.
- Anything beyond that (rate shopping UI, address verification, refunds, tracking, webhooks,
  queues, caching, multi-carrier support) goes into the README "What I'd do next" section, not
  into code.
- Keep layers flat: Controller -> FormRequest -> Service -> Eloquent model. No repository
  pattern, no DTO layer, no events/listeners unless a requirement needs them.
- Do not add a Composer or npm dependency without stating in one line why it is needed. Every
  dependency has to be defensible in the follow-up interview.
- Keep the README "Assumptions" section in sync: when a design decision is made, record it in
  the same change.

## EasyPost API key

- The key lives only in `.env` as `EASYPOST_API_KEY` and is read exclusively through
  `config('services.easypost.key')`. Never call `env()` outside `config/`.
- Never read, print, echo, log, or paste the key value anywhere: not in terminal output,
  commits, tests, fixtures, `.env.example`, README, or comments. Do not `cat .env`, `printenv`,
  or `php artisan config:show services` (they all reveal it).
- Only EasyPost test keys are allowed (prefix `EZTK`). A production key (prefix `EZAK`) buys
  real, billable labels. Never suggest switching to one.
- The key must never reach the browser: no `VITE_*` variable, no Blade inline, no API response.

## EasyPost calls: backend only

- All EasyPost HTTP traffic goes through one backend service class under `app/Services/`. No
  controller, job, or other class talks to `api.easypost.com` directly.
- The React frontend talks only to this app's `/api/*` routes. Never call EasyPost from
  `resources/js`, and never expose EasyPost account IDs or credentials to the browser.
- Label file URLs returned by EasyPost may be stored, but if the label file is downloaded to
  local storage it must be served through an authenticated route, never from `public/`.

## Per-user label isolation

- Every label route requires the `auth:sanctum` middleware.
- Label queries are always scoped to the authenticated user: `$request->user()->labels()` or a
  `LabelPolicy` check. Never `Label::find($id)` / `Label::findOrFail($id)` in a controller.
- Never accept `user_id` from request input. Always take it from the authenticated user.
- Every endpoint that reads or mutates a label must have a feature test proving that a second
  user receives 403 or 404 for a label they do not own. No exceptions.

## Tests never hit the network

- Call `Http::preventStrayRequests()` in `tests/TestCase.php` so any unfaked outbound request
  fails the test loudly. If an official SDK is used instead of the Laravel HTTP client, bind the
  EasyPost service behind an interface and swap in a fake in tests.
- Fake EasyPost responses with `Http::fake()` and assert on the outgoing request
  (`Http::assertSent`), not on real API data.
- A test that would reach `api.easypost.com` is a bug, even with a test key.
- Feature tests run against MySQL `take_home_project_test` (see `phpunit.xml`). Run
  `docker compose up -d` before `composer test`.
